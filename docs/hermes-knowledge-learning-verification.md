6. 探索提交显示的资料范围，模型仅接收所选修订的定义、引用与关系。
7. 轮询结束后移除终态任务 ID，稳定排序、限制历史并保留全部活动任务。

## 实施取舍

1. 使用受管理的隔离工作区并复用现有依赖环境，避免改动主目录。若依赖解析不兼容，需要在隔离环境重新安装。
2. 原 Python 环境缺少声明的可选解析与向量依赖，改用独立 Python 环境安装，并只读复用基础包。部署环境同样需要安装 `requirements-knowledge.txt`。
3. 批量分析按文档修订分别去重、排队，API 返回 `job_ids`，防止重叠选择导致重复分析。调用方需要跟踪全部返回任务；现有 UI 已处理。
