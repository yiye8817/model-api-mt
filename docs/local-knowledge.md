# 本地语义检索与问答

本功能面向工作台中的普通文本问答。在发送到在线意图分析、API 或网页模型之前，先按语义检查本地资料；答案必须通过来源、条件、引用和支持关系校验。默认关闭。插件、独立 Agent/CLI、图像及附件流程沿原有路径处理。

## 安装与连接

在父项目 Python 环境安装可选依赖：

```bash
source .venv/bin/activate
python -m pip install -r requirements-knowledge.txt
```

运行三个独立的本地服务，或为问答复用本地 Hub 已启动的服务：

```bash
llama-server -m /absolute/path/embedding.gguf --embedding --pooling mean --host 127.0.0.1 --port 8011
llama-server -m /absolute/path/reranker.gguf --embedding --pooling rank --host 127.0.0.1 --port 8012
llama-server -m /absolute/path/qa.gguf --host 127.0.0.1 --port 8013
```

以上 pooling 是示例，需要符合具体模型；使用已取得的模型文件，不自动下载。服务能力与参数参照 [llama.cpp server 文档](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)。

点击顶栏“本地知识”→“连接设置”，填写向量、重排的服务 URL、模型名称和明确的权重版本标识；本地问答模型可选。默认只接受回环地址；局域网服务需要单独开启允许选项。公共地址不能配置成本地角色。先保存设置，再点击“检查已保存的连接”。

也可点击“导入配置 JSON”，选择 `/home/yiye/tools/emb/data/knowledge-models/configuration.json` 等配置文件。支持 `{"local_knowledge": {...}}` 包装格式或直接的本地知识配置对象，文件最大 1 MiB。导入会先校验并只合并文件提供的字段；省略的问答配置、开关和范围保留，其他应用设置不会被导入。导入成功后点击“保存”应用配置。

本地问答留空时，连接检查显示“未配置，已跳过（可选）”。资料导入、索引和检索预览仍可使用，普通问答返回 `qa_not_configured` 并按在线兜底开关处理。生成和核验自动本地答案仍需要本地问答服务，以及通过并激活的评测配置；已配置问答但未校准时返回 `uncalibrated`。

## 资料来源

- 未来完整 API 问答：打开相应收集选项后同步；重复保存同一消息不重复入库。历史会话由“导入已有对话”显式导入。旧消息完成性或约束不明时只作为受限参考。
- 网页问答：工作台发起的问答记录原回答和综合结果。网页工具栏的“导入当前可见对话”只读取实际加载、可识别角色的消息；范围和未知上下文会显示。各网站原生发送按钮继续直接在线操作。
- 文档：选择后端本机文件/目录、粘贴明确路径，或从浏览器上传文件/目录。浏览器上传保存相对路径。支持文本、Markdown、常见代码、JSON/CSV/YAML、可提取文本的 PDF、DOCX；扫描件不做 OCR。编码默认识别 UTF-8/BOM，其他编码可显式选择后重试。

单文件最多 20 MiB，单任务最多 2,000 文件，浏览器按最多 40 MiB 的批次上传。解析失败、超限、跳过原因和完成数量分别显示。目录默认排除版本库、依赖、虚拟环境、构建文件、二进制、数据库及敏感文件名。符号链接不能逃逸所选根目录。

不合格文件逐项报告，同批有效文件继续导入；所选本机文件已不存在时报告该路径，不扩大扫描范围。网页完整原始回答与综合分别保存，综合服务失败不撤销已经完整取得的原始候选。

“更新索引”用于手动更新；不后台监控文件。回答和文档引用显示前复核原文件；已变化内容不会继续作为有效旧证据。删除资料清理索引、副本和缓存，不删除原始文件。

## 本地模型评测

仓库附有 `tests/fixtures/local_knowledge/evaluation-documents/` 和两份 JSONL 样例。样例是合成产品资料，只说明评测流程，不代表真实模型已验收。

1. 导入评测文档目录。
2. 勾选“上传评测数据（JSONL）”，分别上传校准集和验证集。
3. 选中两份数据，运行本地评测。每组至少 30 题、15 个正例，六类各至少 5 题，事实/问法家族不能跨组。标准答案不会送入模型。
4. 阈值只由校准集选择；验证集独立运行。失败的验证集不能被反复用于调参；需新的独立验证集。
5. 逐题核对答案及引用支持，再激活通过的配置。必须使用真实端点且有明确权重修订；替身报告无法激活。

门槛为验证集错误本地命中 0，所有本地结论有有效引用，可回答正例的正确命中率至少 60%。报告具体样本、模型/评分/策略指纹和分项结果；这些指标不承诺未评测领域的准确性。模型、评分变换、检索预算或校验策略变化后重新评测；向量模型变化后重新生成索引。

## 状态、取消与引用

消息标注“本地资料回答”“历史问答复用”或“在线回答”。引用可定位文件行、PDF 页、DOCX 段落/表格及原会话消息；网页引用打开原 URL。历史模型回答保持这一来源性质，不因保存或点赞升级为权威事实。

停止会取消本地推理及已发起的网页采集。取消不进入在线兜底，迟到结果不覆盖新请求。已经发送到网站的请求无法撤回，站点停止按钮可识别时会尝试停止生成。索引任务单独提供停止按钮。

`GET /api/knowledge/requests/<request_id>` 显示本地阶段、诊断和实际在线请求次数。网页计数来自已发送事件，与回答是否完整、综合是否成功分别记录。

关闭本地功能后走原有在线路径。本地未命中且关闭在线兜底时显示原因；没有在线 provider 也可创建会话使用本地问答，需要兜底时再报告配置缺失。

## 保存、恢复与验证

数据位于 `data/local-knowledge/`，SQLite 为修订状态的权威来源，Chroma 保存显式生成的本地向量。[Chroma 客户端文档](https://docs.trychroma.com/reference/python/client)

备份时停止父服务，再一起复制该目录及应用会话/设置；不要只复制向量目录。启动会恢复未完成的索引及会话同步。中断的评测报告不能激活，重新评测应使用独立验证集。索引失败不使不完整修订参与回答。

当前实现和确定性验证针对本机 Linux。运行检查：

```bash
PYTHONPATH=desktop-agent/src .venv/bin/python -m pytest
npm run test:knowledge
npx tsc --noEmit
npm run build
npm run test:web-chat
```

真实模型精度状态见 [验收报告](local-knowledge-evaluation-report.md)。
