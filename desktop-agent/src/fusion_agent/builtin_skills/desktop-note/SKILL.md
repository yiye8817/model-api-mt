# 在桌面编辑器中输入便笺

1. 确认用户给出的便笺正文与目标本地文本编辑器。使用 `desktop.observe {}` 获取当前 `observation_id`、屏幕尺寸和 OCR 文本框。
2. 只依据可观察到的 OCR 文本和用户指定的目标操作。OCR 返回 `available:false`、目标不明确、编辑区坐标无法判断时，停止坐标操作，说明需要用户把目标编辑器置于前台，或改用工作区 `files.write` 保存文本。
3. 优先使用用户已经聚焦的编辑区。确实需要点击且能定位目标时，用 `desktop.click`：`{"observation_id":"刚返回的ID","x":120,"y":200}`。这里的坐标仅展示参数形状，实际操作必须来自真实观察，不能照抄。点击后需要用 `desktop.verify` 的 `text_contains` 检查与操作目标相关的可见变化；OCR 无法证明焦点且没有相关变化时应停止，说明需要用户聚焦编辑区后重新运行任务。不能用鼠标坐标或一直存在的标题冒充焦点核验。
4. 调用 `desktop.observe {}` 获取新观察。确认目标明确且没有待核验动作，才使用 `desktop.type`：`{"observation_id":"新的ID","text":"用户要求的便笺正文"}`。
5. 输入后调用 `desktop.verify {"text_contains":"用户要求的便笺正文"}`，工具会重新截图并检查 OCR；普通观察不会解除待核验状态。OCR 看不到完整正文时报告输入结果未核验，不能声称任务完成或文件已保存。只有用户要求保存时，才按编辑器实际状态执行保存操作，随后检查相关结果；可见文字核验不等于文件落盘核验，工作区文件可另用 `files.read` 检查。

本项目将桌面截图保存在本地供人查看，并通过 OCR 将文字与坐标提供给模型。当前模型接口是文本输入，模型并没有直接看见截图。OCR 不提供可靠视觉理解：空白编辑区、图标、遮挡和缩放可能让坐标无法判断，此时不要猜测点击。

`desktop.type` 的中文输入依赖可用的剪贴板后端。`desktop.hotkey` 参数为 `{"observation_id":"最新ID","keys":["ctrl","s"]}`；快捷键必须匹配当前明确识别的编辑器操作。桌面工具只支持 X11；在 Wayland 返回不支持时，不能通过技能文字绕过系统限制。
